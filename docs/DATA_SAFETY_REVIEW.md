# Google Play Data Safety — source review

Status: **NOT SUBMITTED / NOT FINAL**. This is a source-level assessment, not a completed Play Console declaration.

## Current implementation observations
- The merged manifest has not yet been generated by a successful Android build. The source manifest declares no `INTERNET`, contacts, phone, camera, location, or broad storage permission.
- POS profile, categories, products, stock, transaction headers, transaction items, and preferences are stored locally using Room/SQLite and Preferences DataStore.
- The source dependency list contains AndroidX/Jetpack, Room, Kotlin Coroutines, DataStore, Compose, and Navigation. No Firebase, analytics, crash reporting, ad SDK, or remote POS backend is intentionally included.
- There is no user account or registration.
- Manual JSON backup exports user-selected records through Android Storage Access Framework. The file is not encrypted by this app.
- Receipt sharing invokes Android's system chooser only after the user selects Share. The user chooses the receiving app.
- The app does not itself upload POS data to a BERKAH TIGA PUTERI server.

## Policy interpretation to validate
Google Play's current Data Safety help says data processed only locally on-device and not sent off-device does not need to be disclosed as collected. It defines sharing to include on-device transfers to another app, but lists a specific user-initiated action where the user reasonably expects the transfer as an exception that need not be disclosed as sharing.

The manual receipt share and user-selected export destination appear to be user-initiated transfers. This interpretation must be checked against the actual release behavior and current Play Console form before submission. Do not treat this note as a final declaration.

## Candidate answers if release inspection confirms no additional data flows
- Data collected off-device by BERKAH POS: candidate **No**.
- Data shared with third parties: candidate **No** for developer-operated sharing; user-triggered share/export should be reviewed against the user-initiated-action exception.
- Data processed locally: products, store profile, stock, transactions, and receipt details.
- Encryption in transit: there is no app-operated POS network transfer in the intended build. JSON backup files are not encrypted at rest by the app.
- Account deletion: not applicable because the app has no account creation or login. Users can remove app-local data through Android app storage controls/uninstall; an explicit in-app “clear all POS data” control is not currently implemented.
- SDK disclosures: inspect every transitive dependency and any manifest contributions before selecting the final answers.
